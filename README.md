# opencode-compact-notes

High-fidelity compaction summaries for [OpenCode](https://opencode.ai).

When OpenCode compacts a session, it replaces the conversation with a summary generated by a dedicated model call. The
default summary prompt is short and generic, so the result often drops the details that matter after compaction: exact
values, paths, commands, rejected alternatives, mid-task corrections, and environment gotchas. The next instance then
re-does work it already had (re-running commands, re-reading files, re-asking questions).

This plugin adds nothing to normal requests. It registers exactly one hook, `compaction`, and pushes a
completeness-first contract into the system instructions of that summary call. OpenCode keeps generating the summary
itself; the contract only tells the summarizer what must survive.

## Install

Published from Git:

```sh
opencode plugin add github:JoshuaCidbit/opencode-compact-notes
```

Pin a revision when you want reproducible installs:

```sh
opencode plugin add github:JoshuaCidbit/opencode-compact-notes#<sha-or-tag>
```

Local development checkout:

```jsonc
// ~/.config/opencode/opencode.json(c)
{
  "plugins": ["/absolute/path/to/opencode-compact-notes"]
}
```

The directory must contain `package.json` with `name` and `exports`. Relative paths resolve from the config file that
declares them.

Update or remove with `opencode plugin update` / `opencode plugin remove`.

## Contract

The contract ships as [`compact.md`](./compact.md) next to the plugin. It is deliberately universal: it prescribes what
to preserve, never repo-specific values. Nine blocks:

1. Objective and requirements, including mid-task corrections and reversals.
2. Literal values verbatim (limits, paths, names, keys, versions, IDs).
3. Decisions plus rejected alternatives and why.
4. Errors, root causes, and look-alike failures that must not be retried.
5. Commands executed and what their output proved.
6. Files and artifacts, with verified vs assumed state.
7. Environment gotchas that cannot be rediscovered from the code.
8. Status (done/pending/blocked) and the exact next action.
9. Uncertainty discipline: label unverified knowledge instead of dropping it.

Header rule: optimize for completeness, not brevity.

## Override the contract

Use the object form to point at a different file, for example to tune wording per machine without forking:

```jsonc
{
  "plugins": [
    {
      "package": "opencode-compact-notes",
      "options": { "path": "/home/me/my-compaction-contract.md" }
    }
  ]
}
```

## Behavior and limits

- Hook registered: `compaction` only. No tools, commands, TUI or GUI parts, no extra permissions.
- Cost outside compaction: zero. The contract travels only in the summary model call.
- Does not change the compaction threshold, `keep.tokens`, `buffer`, or the compaction model; those stay in
  `opencode.json`.
- Does not write or replace the summary (`event.result` is untouched), and does not persist durable state. For that,
  keep a plan or notes file.
- Summary quality still depends on the summarizer model. A weak model produces a weak summary; the contract can only
  frame what is worth keeping.
- Defensive by design: if the contract cannot be read or the event shape changes, the plugin logs and lets native
  compaction proceed.

## Tested with

Compaction model is orthogonal to this plugin: set `agents.compaction.model` and compare. The A/B below used the same
sessions and the same contract, so the difference is the summarizer, not the wording.

| Summarizer | Same transcript (~11k in) | Long session (~84k in) | Kept |
| --- | --- | --- | --- |
| `opencode/deepseek-v4.1-flash-free` | 5,036 B / 1,341 out | 5,255 B / 1,724 out | literal values, rejected alternatives, root cause vs look-alike, unverified tags |
| `openrouter/nvidia/nemotron-3-ultra-550b-a55b:free` | 1,380 B / 385 out | 2,525 B / 780 out | objective, decisions, status, next move; dropped errors/root cause, commands+evidence, uncertainty tags |

**Result:** DeepSeek wins for long sessions — roughly 2.5–3.5x more summary and it preserves the details that are
expensive to re-derive (exact commands, rejected options, quota vs hard-limit distinctions). Nemotron stays readable
and organized and is fine for short, linear sessions.

Both are free tiers and their availability, limits, and quality can change. Any strong instruction-following model
works; the point of the table is that a weaker summarizer produces a weaker summary even with a good contract.

Note that `keep.tokens` is approximate and the retained tail has long tool output shortened, so verbatim detail that
lives inside old tool results survives only through the summary. Keep durable state (plans, notes) in a file when it
must not be lost.

Pair it with a slightly larger recent-context window when you want more verbatim tail, e.g.:

```jsonc
{
  "compaction": { "auto": true, "buffer": "25%", "keep": { "tokens": 24000 } }
}
```
